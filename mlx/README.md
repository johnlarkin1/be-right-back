# Be Right Back - MLX Training Pipeline

LoRA fine-tuning pipeline using Apple's MLX framework for training personalized chatbot personas.

## Overview

This directory contains Python scripts for training LoRA adapters on conversation data exported from iMessage. The training process:

1. Loads exported JSONL conversation data
2. Loads a base model (Qwen3.5-9B by default)
3. Adds LoRA adapter layers
4. Fine-tunes the adapter on conversation history
5. Saves the adapter for inference

## Prerequisites

- **macOS with Apple Silicon** (M1/M2/M3)
- **Python 3.10+**
- **uv** package manager ([install instructions](https://docs.astral.sh/uv/))
- **8GB+ RAM** (16GB recommended)
- **10GB+ free disk space** for models

## Setup

### 1. Install `uv` (if not already installed)

```bash
# via Homebrew
brew install uv

# or via standalone installer
curl -LsSf https://astral.sh/uv/install.sh | sh
```

### 2. Create Python virtual environment

The virtual environment lives in `~/.be-right-back/mlx-venv/` (production location):

```bash
# create virtual environment
uv venv ~/.be-right-back/mlx-venv

# install dependencies
uv pip install --python ~/.be-right-back/mlx-venv/bin/python -e .
```

Alternatively, install directly from pyproject.toml:

```bash
cd mlx
uv pip install --python ~/.be-right-back/mlx-venv/bin/python .
```

**Note for distribution:** When shipping the app, we'll need to either:
- Bundle `uv` with the app and ensure it's installed
- Fall back to standard `python3 -m venv` and `pip` if `uv` is unavailable
- The Rust backend should check for `uv` availability and handle both cases

### 3. Verify installation

```bash
~/.be-right-back/mlx-venv/bin/python -c "import mlx; import mlx_lm; print('MLX installed successfully')"
```

## Usage

### Basic Training

Train a LoRA adapter on exported conversation data:

```bash
~/.be-right-back/mlx-venv/bin/python -m core.train \
  --data ~/.be-right-back/data/processed/alice.jsonl \
  --output ~/.be-right-back/models/personas/alice \
  --contact-id alice \
  --contact-name "Alice"
```

### Advanced Options

```bash
~/.be-right-back/mlx-venv/bin/python -m core.train \
  --data ~/.be-right-back/data/processed/bob.jsonl \
  --output ~/.be-right-back/models/personas/bob \
  --contact-id bob \
  --contact-name "Bob" \
  --base-model mlx-community/Qwen3.5-9B-4bit \
  --max-steps 1500 \
  --learning-rate 0.0001 \
  --batch-size 4 \
  --lora-rank 8 \
  --lora-alpha 16 \
  --save-every 200
```

### Command-line Arguments

| Argument | Description | Default |
|----------|-------------|---------|
| `--data` | Path to JSONL training data | **required** |
| `--output` | Output directory for adapter | **required** |
| `--contact-id` | Contact identifier | optional |
| `--contact-name` | Contact display name | optional |
| `--base-model` | Base model name | `mlx-community/Qwen3.5-9B-4bit` |
| `--max-steps` | Maximum training steps | `500` |
| `--learning-rate` | Learning rate | `1e-5` |
| `--batch-size` | Batch size | `1` |
| `--lora-rank` | LoRA rank | `16` |
| `--lora-alpha` | LoRA alpha | `32` |
| `--save-every` | Checkpoint frequency | `200` |

## Training Data Format

The training script expects JSONL files with chat completion format:

```jsonl
{"messages": [{"role": "user", "content": "hey how's it going?"}, {"role": "assistant", "content": "good! just got back from the gym"}]}
{"messages": [{"role": "user", "content": "wanna grab dinner later?"}, {"role": "assistant", "content": "yeah for sure! where you thinking?"}]}
```

This format is automatically generated by the `be-right-back export` command.

## Output Structure

After training, the output directory contains:

```
~/.be-right-back/models/personas/you/
├── adapter/                   # LoRA adapter files (MLX format)
│   ├── adapter_config.json
│   └── adapter_weights.safetensors
└── metadata.json             # Training metadata
```

### Metadata File

The `metadata.json` file contains training information:

```json
{
  "contact_id": "alice",
  "contact_name": "Alice",
  "base_model": "mlx-community/Qwen3.5-9B-4bit",

  "training_examples": 342,
  "training_config": { ... },
  "training_start": "2025-01-15T10:30:00Z",
  "training_duration_seconds": 1847.23,
```

## Troubleshooting

### Out of Memory (OOM)

If training fails with memory errors, try:

1. Reduce batch size: `--batch-size 2`
2. Reduce max sequence length (edit `core/config.py` - `max_seq_length: 1024`)
3. Use smaller LoRA rank: `--lora-rank 4`

### Model Download Fails

On first run, the script downloads the base model (~6GB). If this fails:

1. Check internet connection
2. Try manually downloading from HuggingFace:
   ```bash
   huggingface-cli download mlx-community/Qwen3.5-9B-4bit
   ```

### Import Errors

If you get `ModuleNotFoundError`:

```bash
# check installed packages
~/.be-right-back/mlx-venv/bin/python -m pip list

# reinstall dependencies
uv pip install --python ~/.be-right-back/mlx-venv/bin/python -e mlx
```

## Configuration

Default hyperparameters are defined in `core/config.py`. Key settings:

```python
# LoRA configuration
rank = 8                    # adapter rank (higher = more parameters)
alpha = 16                  # scaling factor (usually 2*rank)
dropout = 0.05              # regularization

# Training configuration
learning_rate = 1e-4        # conservative for small datasets
batch_size = 4              # fits in 8GB RAM
max_steps = 1000            # ~3-4 epochs for typical conversation
warmup_steps = 100          # gradual LR warmup
```

Adjust these in `core/config.py` or override via command-line arguments.
