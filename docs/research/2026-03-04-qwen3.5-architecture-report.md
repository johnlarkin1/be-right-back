## 1. What Is Qwen3.5?

Qwen3.5 is Alibaba's March 2026 language model family. It replaces the pure-Transformer Qwen3 with a **hybrid architecture** that mixes two kinds of attention:

- **Gated DeltaNet** (linear attention) — 75% of layers
- **Standard full softmax attention** — 25% of layers

The result is a model that maintains Transformer-level quality while dramatically reducing memory usage at inference time. The 9B variant beats OpenAI's GPT-OSS-120B on multiple benchmarks while being 13x smaller.

Key specs across the family:

| Model | Parameters | Layers | Hidden Dim | Context | Vocab |
|-------|-----------|--------|------------|---------|-------|
| 0.8B | 0.8 billion | 24 | 1024 | 262K | 248,320 |
| 2B | 2 billion | 24 | 2048 | 262K | 248,320 |
| 4B | 4 billion | 32 | 2560 | 262K | 248,320 |
| 9B | 9 billion | 32 | 4096 | 262K → 1M | 248,320 |
| 397B-A17B | 397B (17B active) | 60 | 4096 | 262K | 248,320 |

All models are natively multimodal (vision + language), support thinking mode, and use Multi-Token Prediction (MTP) for faster inference.

## 2. The Hybrid Architecture

Every Qwen3.5 model follows a strict repeating pattern:

```
3 × (Gated DeltaNet → FFN) → 1 × (Full Attention → FFN)
```

This repeats for the entire depth of the model. For the 9B with 32 layers:

```
Layer  0: DeltaNet → FFN
Layer  1: DeltaNet → FFN
Layer  2: DeltaNet → FFN
Layer  3: Full Attention → FFN    ← every 4th layer
Layer  4: DeltaNet → FFN
Layer  5: DeltaNet → FFN
Layer  6: DeltaNet → FFN
Layer  7: Full Attention → FFN    ← every 4th layer
...
Layer 28: DeltaNet → FFN
Layer 29: DeltaNet → FFN
Layer 30: DeltaNet → FFN
Layer 31: Full Attention → FFN    ← every 4th layer
```

The config encodes this explicitly via the `layer_types` array and `full_attention_interval: 4`.

**Why this matters**: DeltaNet layers have a **fixed-size state** (`d × d` matrix) that doesn't grow with context length. Only the full attention layers (25% of the total) need a KV cache that grows linearly with context. This is what makes 262K context feasible on consumer hardware.

## 3. Understanding Standard Attention (The Baseline)

Before diving into DeltaNet, let's establish what standard attention does. Given an input sequence of `n` tokens, each projected into queries (`Q`), keys (`K`), and values (`V`):

```
Attention(Q, K, V) = softmax(Q · K^T / √d) · V
```

This computes a **weighted average of all values**, where the weights come from how similar each query is to each key (via dot product, normalized by softmax).

**The good**: Every token can attend to every other token. The softmax creates a sharp, selective attention pattern — the model can precisely focus on the most relevant tokens.

**The bad**:
- **O(n²) compute**: Every token compares against every other token
- **O(n·d) KV cache**: At inference, you store every past key and value. For a 262K context with 256-dim heads, that's 67 million elements per head per layer — and it keeps growing with each new token

---

## 4. Linear Attention and Its Problems

### The Core Idea

What if we drop the softmax? Without it, the attention equation becomes:

```
O = (Q · K^T) · V
```

By the associativity of matrix multiplication, we can rewrite this as:

```
O = Q · (K^T · V)
```

Instead of computing the `n × n` attention matrix first (O(n²)), we compute `K^T · V` first — a `d × d` matrix — then multiply by each query. This is **O(n·d²)** instead of O(n²·d).

### The Recurrent View

Even more powerfully, linear attention can be expressed as an RNN. Define a **state matrix** `S_t` that accumulates key-value associations:

```
S_t = S_{t-1} + v_t · k_t^T        (state update: add new association)
o_t = S_t · q_t                      (output: query the accumulated state)
```

This is beautiful: at inference, you maintain a fixed `d × d` state matrix. Each new token updates the state and queries it in O(d²) — no matter how long the context is. No growing KV cache.

### The Fatal Flaw: It Can Only Add, Never Erase

The update rule `S_t = S_{t-1} + v_t · k_t^T` only **adds** new key-value pairs. It can never remove or update old ones. When you query key `k_j`, you get:

```
S · k_j = v_j + Σ_{i≠j} (k_i^T · k_j) · v_i
                  ↑                ↑
             correct answer    retrieval error (noise from all other keys)
```

The error term grows with every token added. Since at most `d` vectors can be orthogonal in `d`-dimensional space, the state eventually saturates and retrievals become unreliable.

**Analogy**: Imagine a whiteboard where you can only write, never erase. Eventually it's so full that you can't read anything clearly. That's linear attention's memory problem.

## 5. The Delta Rule: Fixing Linear Attention

### From Machine Learning, Circa 1960

The delta rule (Widrow-Hoff rule, 1960) is one of the oldest ideas in machine learning. It's simply **online gradient descent** on a squared error loss. DeltaNet (Yang et al., 2024) applies it to the linear attention state update.

### The Key Insight: Erase Before Write

Instead of blindly adding `v_t · k_t^T`, first check what the state *already* associates with key `k_t`, then correct the error:

**Loss at each timestep:**
```
L_t(S) = ½ · ||S · k_t - v_t||²
```

This asks: "how wrong is the current state's prediction for key `k_t`?"

**Gradient descent update:**
```
S_t = S_{t-1} - β_t · ∇L_t(S_{t-1})
    = S_{t-1} - β_t · (S_{t-1} · k_t - v_t) · k_t^T
```

Expanding:
```
S_t = S_{t-1} - β_t · (S_{t-1} · k_t) · k_t^T + β_t · v_t · k_t^T
       ↑              ↑                                  ↑
    old state     ERASE old value for k_t           WRITE new value for k_t
```

This is the **erase-write mechanism**: the model first erases whatever was previously associated with key `k_t`, then writes the new value `v_t`. The learning rate `β_t` (data-dependent, between 0 and 1) controls how aggressively this happens.

**Back to the whiteboard analogy**: Instead of writing over old text (linear attention), DeltaNet first erases the specific area it needs, then writes new content clearly.

### Why This Works Mathematically

After the update, querying key `k_t` gives:
```
S_t · k_t = (1 - β_t) · S_{t-1} · k_t + β_t · v_t
```

When `β_t = 1`, we get `S_t · k_t = v_t` exactly — perfect retrieval with zero error. The delta rule selectively overwrites just one key-value association without disturbing others (assuming orthogonal keys).

### Making It Trainable: The WY Representation

The recurrence is sequential, which is terrible for GPU training. The key trick is that the cumulative product of transition matrices admits a compact **WY decomposition**:

```
∏_{i=1}^{t} (I - β_i · k_i · k_i^T) = I - Σ_{i=1}^{t} w_i · k_i^T
```

where the `w` vectors are computed recursively. This enables a **chunkwise parallel** algorithm:

1. Divide the sequence into chunks of size `C`
2. Within each chunk: parallel computation (like standard attention)
3. Across chunks: propagate the `d × d` state sequentially

**Complexity**: O(n·d² + (n/C)·d³) time, O(C·d²) space — a practical middle ground between purely recurrent O(n·d²) and parallel O(n²·d).

## 6. Gated DeltaNet: The Full Picture

Gated DeltaNet (Karan et al., ICLR 2025, from NVIDIA) is what Qwen3.5 actually uses. It extends DeltaNet with a **scalar decay gate** borrowed from Mamba2.

### The Complete Update Rule

```
S_t = α_t · S_{t-1} - β_t · (S_{t-1} · k_t - v_t) · k_t^T
```

Where:
- **α_t ∈ (0, 1)** — the **decay gate**: controls global memory retention
- **β_t ∈ (0, 1)** — the **update gate**: controls delta rule strength

### Why Both Gates Matter

DeltaNet alone has a problem: the delta rule can only update associations for keys similar to the current key `k_t`. If you need to rapidly clear *all* memory (e.g., at a topic boundary), the delta rule is too surgical.

The decay gate `α_t` provides **wholesale erasure** — multiplying the entire state by a scalar near 0 effectively resets it. Combined:

| α_t | β_t | Behavior |
|-----|-----|----------|
| → 0 | any | **Hard reset**: clear all memory |
| → 1 | → 0 | **Pure retention**: keep everything, add nothing |
| → 1 | → 1 | **Pure delta rule**: selective overwrite |
| 0.5 | 0.5 | **Mixed**: partial decay + partial update |

This gives the model **fine-grained control** over its memory at every timestep.

### How the Gates Are Computed

The decay gate `α_t` uses Mamba-style parameterization:

```python
# A_log and dt_bias are learnable per-head parameters
alpha_log = -exp(A_log) · softplus(W_α(x) + dt_bias)
α_t = exp(alpha_log)
```

- `A_log` — learnable, shape `[num_heads]`, initialized from `log(uniform(0, 16))`
- `dt_bias` — learnable, shape `[num_heads]`, initialized to ones
- `W_α` — linear projection from `hidden_size → num_heads`

The update gate is simpler:
```python
β_t = sigmoid(W_β(x))
```

### Full Forward Pass of a Gated DeltaNet Layer

```
Input x
  │
  ├─→ in_proj_qkv(x) ──→ split into Q, K, V
  │     │
  │     └─→ conv1d (causal, kernel=4) ──→ Q', K', V'
  │           │
  │           ├─→ L2-normalize Q', K'
  │           │
  │           └─→ Gated DeltaNet recurrence:
  │                 S_t = α_t · S_{t-1} - β_t · (S_{t-1}·k_t - v_t)·k_t^T
  │                 context = S_t · q_t
  │
  ├─→ in_proj_a(x) + dt_bias ──→ α_t (via A_log and softplus)
  ├─→ in_proj_b(x) ──→ β_t (via sigmoid)
  ├─→ in_proj_z(x) ──→ output gate g_t (via SiLU)
  │
  └─→ norm(context) · g_t ──→ out_proj ──→ output
```

### The State Is Fixed-Size

The state `S` has shape `[batch, num_heads, head_dim, head_dim]`. For Qwen3.5-9B with 16 heads and 128-dim:

```
State per layer = 16 heads × 128 × 128 = 262,144 floats = 1 MB (fp32)
```

Compare with full attention's KV cache at 262K context:
```
KV cache per layer = 2 × 262,144 tokens × 256 dim × 4 heads = 536 million floats = 2 GB (fp32)
```

That's a **2000× reduction** in per-layer memory for DeltaNet vs full attention at 262K context.

## 7. Weight Structure in Practice

When you inspect a Qwen3.5 model, weights use the prefix `language_model.model.layers.{N}.*`:

### DeltaNet Layers (75% of layers)

| Weight | Purpose | Shape (9B) |
|--------|---------|------------|
| `linear_attn.in_proj_qkv` | Fused Q, K, V projection | `[4096, Q+K+V dims]` |
| `linear_attn.in_proj_a` | Decay gate projection (→ α) | `[4096, 16]` |
| `linear_attn.in_proj_b` | Update gate projection (→ β) | `[4096, V_dim]` |
| `linear_attn.in_proj_z` | Output gate projection | `[4096, V_dim]` |
| `linear_attn.out_proj` | Output projection | `[V_dim, 4096]` |
| `linear_attn.conv1d` | Causal 1D conv, kernel=4 | depthwise, groups=channels |
| `linear_attn.A_log` | State matrix (log-space) | `[16]` |
| `linear_attn.dt_bias` | Delta-time bias | `[16]` |
| `linear_attn.norm` | RMSNorm on output | `[V_dim]` |

The `in_proj_qkv` is a **fused** projection — Q, K, V are computed together and then split. This differs from the reference NVlabs implementation which uses separate projections.

The `conv1d` is a **causal short convolution** (kernel size 4, with padding 3) applied to the QKV features before attention. This provides local context mixing — a pattern borrowed from Mamba. Think of it as giving each token a small window of local context before the global attention mechanism operates.

`A_log` and `dt_bias` are tiny per-head scalars that parameterize the decay gate. The naming comes from the Mamba/S4 tradition where `A` is the state transition matrix and `dt` is the discretization timestep.

### Full Attention Layers (25% of layers)

| Weight | Purpose | Shape (9B) |
|--------|---------|------------|
| `self_attn.q_proj` | Query projection | `[4096, 16 × 256]` |
| `self_attn.k_proj` | Key projection | `[4096, 4 × 256]` |
| `self_attn.v_proj` | Value projection | `[4096, 4 × 256]` |
| `self_attn.o_proj` | Output projection | `[16 × 256, 4096]` |
| `self_attn.q_norm` | Query RMSNorm | `[256]` |
| `self_attn.k_norm` | Key RMSNorm | `[256]` |

Full attention uses **Grouped Query Attention (GQA)**: 16 query heads, 4 KV heads (4:1 ratio). Head dimension is 256.

RoPE is applied with `partial_rotary_factor=0.25`, meaning only the first 64 of 256 head dimensions receive rotary position encoding.

### MLP (Every Layer, Both Types)

| Weight | Purpose | Shape (9B) |
|--------|---------|------------|
| `mlp.gate_proj` | Gate for SwiGLU | `[4096, 12288]` |
| `mlp.up_proj` | Up projection | `[4096, 12288]` |
| `mlp.down_proj` | Down projection | `[12288, 4096]` |

SwiGLU activation: `output = down_proj(SiLU(gate_proj(x)) ⊙ up_proj(x))`

## 8. Comparison with Other Architectures

### The Landscape of Efficient Attention

All sub-quadratic attention variants can be viewed through the lens of **state-space models with different gating**:

```
General form: S_t = G_t ⊙ S_{t-1} + v_t · k_t^T
```

What varies is how the gate `G_t` is structured:

| Architecture | Gate `G_t` | Update Mechanism | Key Trade-off |
|---|---|---|---|
| **Standard Attention** | N/A (computes full n×n matrix) | Softmax-weighted sum | Best quality, O(n²) cost |
| **Linear Attention** | `I` (identity, no gating) | Pure additive | No forgetting → state saturates |
| **RetNet** | `γ · 1·1^T` (fixed scalar) | Exponential decay | Too aggressive — forgets everything uniformly |
| **GLA** | `1 · α_t^T` (per-key gate) | Data-dependent key-wise decay | Fine-grained but complex training |
| **RWKV** | Channel-directed | Token shift + channel mixing | Efficient but less expressive |
| **Mamba / Mamba2** | `exp(-Δ_t · exp(A))` / `γ_t · 1·1^T` | Input-conditioned SSM | Good general performance, wholesale erasure only |
| **DeltaNet** | Delta rule gradient descent | Selective erase-write | Surgical updates, but can't do rapid full reset |
| **Gated DeltaNet** | `α_t · I` + delta rule | Decay + selective erase-write | **Best of both**: wholesale + surgical |

### Complexity Comparison

| Architecture | Training (per layer) | Inference (per step) | State Size |
|---|---|---|---|
| **Full Attention** | O(n² · d) | O(n · d) — grows! | O(n · d) — grows! |
| **Linear Attention** | O(n · d²) | O(d²) — constant | O(d²) — fixed |
| **DeltaNet** | O(n·d² + n/C·d³) | O(d²) — constant | O(d²) — fixed |
| **Gated DeltaNet** | O(n·d² + n/C·d³) | O(d²) — constant | O(d²) — fixed |
| **Mamba** | O(n · d) | O(d) — constant | O(d) — fixed |

The critical insight: **DeltaNet/Gated DeltaNet have constant O(d²) inference cost per step**, regardless of context length. Full attention's cost grows linearly with context. At 262K tokens, this difference is massive.

### Empirical Results

From the Gated DeltaNet paper (ICLR 2025):

- At 1.3B parameters, 100B training tokens: Gated DeltaNet consistently surpasses Mamba2, DeltaNet, and GLA on perplexity, common-sense reasoning, in-context retrieval, and length extrapolation
- In hybrid configurations (mixing with full attention): Gated DeltaNet + HGRN-2 consistently performs best, surpassing the pure Transformer baseline by 2-5 percentage points on recall tasks
- The combination of gating + delta rule outperforms either mechanism alone

## 9. Why 3:1 Hybrid Works

### The Theory

Purely linear attention models have a fundamental limitation: the `d × d` state can only store `d` key-value associations perfectly. For complex reasoning that requires comparing many token pairs simultaneously (e.g., multi-hop reasoning, code understanding), the state becomes a bottleneck.

Full attention doesn't have this limitation — it can compare any pair of tokens — but it costs O(n²).

The hybrid approach gives you:
- **DeltaNet layers** (75%): Efficiently process the bulk of context, maintaining a compressed summary of everything seen so far. Good for: general language modeling, entity tracking, local patterns
- **Full attention layers** (25%): Perform precise pairwise comparisons when needed. Good for: complex reasoning, long-range dependencies, exact retrieval

### The Evidence

1. **Qwen3-Next** (September 2025): An 80B model using the same 3:1 architecture but trained on only 15T tokens. Underperformed Qwen3-32B (pure Transformer) — initially suggesting the architecture was flawed. The real issue was insufficient training data for the hybrid to reach its potential.

2. **Qwen3.5** (March 2026): With more training data, the architecture proved itself dramatically. The 9B model beats much larger models on standard benchmarks while being feasible to run on a MacBook.

3. **Systematic analysis** (arXiv:2507.06457): A study of hybrid linear attention architectures found that the 3:1 ratio provides the optimal trade-off between compute efficiency and model quality.

### Why Not 100% DeltaNet?

Pure DeltaNet (no full attention layers) loses 2-5 percentage points on recall-intensive tasks. The full attention layers act as "checkpoints" in the network where the model can perform precise retrieval over the entire context. Without them, the compressed state loses too much information for tasks requiring exact recall.

### Why Not 50/50?

More full attention layers means more KV cache memory. At 50%, you'd lose much of the memory advantage. The 3:1 ratio is the sweet spot: 75% memory savings from DeltaNet layers while keeping enough full attention for quality.

## 11. Implications for LoRA Fine-Tuning

### Which Weights to Target

For Be Right Back's persona training, we target these modules:

**DeltaNet layers:**
- `linear_attn.out_proj` — the output projection is the highest-impact target for adapting generation style

We deliberately skip `in_proj_qkv`, `in_proj_a`, `in_proj_b`, `in_proj_z` because:
- The fused QKV projection has complex internal structure
- The gate projections (`in_proj_a`, `in_proj_b`) control memory dynamics — modifying them risks destabilizing the recurrence
- `out_proj` alone gives sufficient adaptation for persona style

**Full attention layers:**
- `self_attn.q_proj`, `k_proj`, `v_proj`, `o_proj` — standard targets, well-understood from Transformer LoRA literature

**MLP (all layers):**
- `mlp.gate_proj`, `mlp.up_proj`, `mlp.down_proj` — the feedforward layers encode most of the factual and stylistic knowledge

### Why Qwen3 Adapters Are Incompatible

Qwen3 is a standard Transformer with `self_attn.*` in every layer. Qwen3.5 replaces 75% of those with `linear_attn.*`. A LoRA adapter trained on Qwen3-4B targets weights that simply don't exist in Qwen3.5's architecture — different layer names, different dimensions, different semantics. Loading such an adapter would either crash or produce nonsense.

### Dynamic Layer Count

The training pipeline now detects `num_layers` dynamically:

```python
num_model_layers = len(model.model.layers)  # or model.language_model.model.layers
```

Instead of the old hardcoded `num_layers=16`, which was wrong even for Qwen3-4B (which had 32 layers).
